🎯 Core Learning Goals
By completing this assignment, your team will master the following universal software engineering principles:

Architectural Patterns: Design a dynamic Coordinator + Worker topology that manages complex state, conditional routing, handoffs, and deterministic loops in an asynchronous multi-agent system.

Failure Mode Awareness: Identify, programmatically reproduce, and mitigate the 6 critical failure modes (infinite loops, silent failures, rogue actions, cascade failures, data privacy leaks, and context window explosion) that plague production-grade agents.

Guardrail Engineering: Implement code-based guardrails (schema enforcement, dynamic tool whitelists, context pruning) that programmatically prevent failures, moving beyond fragile prompt engineering.

Contract-First Design: Define and enforce a rigid, shared schema (Contract) for data state passing between agents, ensuring complete type safety and structural integrity across the graph.

System Integration: Merge individual guardrail layers into a single, cohesive state machine, ensuring error-handling nodes gracefully route data without deadlocking the graph.

Professional Communication: Articulate a quantified, domain-specific engineering story about a failure you isolated and solved, formatted explicitly for technical job interviews.

📋 The 6 Critical Failure Modes & Engineering Guardrail Requirements
To secure full credit, your guardrail cannot be a soft prompt amendment (e.g., "Don't loop forever"). It must be implemented in code.

1. Infinite Graph Loops (Student 1)
The Failure: The Coordinator node continuously re-routes tasks back to an upstream node because the LLM fails to reach a terminating condition, threatening to drain budget API tokens.

The Guardrail: Implement a strict, deterministic state["round_number"] tracker directly into the LangGraph routing logic. If round_number >= 5, short-circuit the graph flow, gracefully degrade, and route straight to a final partial state output node.

2. Silent Hallucinations & Structural Failures (Student 2)
The Failure: Worker A receives unformatted data, outputs a confident text answer that misses critical domain identifiers, causing silent processing failures downstream.

The Guardrail: Force Worker A to use an explicit schema object via .with_structured_output(ContractSchema). Catch raw LLM schema parsing validation errors programmatically within an error handling wrapper, then route the error exception text back to the node once for an automated self-correcting retry.

3. Rogue Tool Execution (Student 3)
The Failure: Worker B receives a prompt that triggers a jailbreak or an un-vetted tool invocation parameter, generating a destructive call payload.

The Guardrail: Build a functional, dynamic tool runtime execution middleware. Intercept the LLM's requested tool call array before execution. Validate the request against a hardcoded lookup configuration matrix. If the tool or argument parameters violate the runtime permissions, throw an InvalidToolCallException and abort execution.

4. Downstream Cascade Failure (Student 4)
The Failure: Worker B passes malformed, unvalidated output data across the state directly into Worker C, causing runtime application crashes or arithmetic type errors in downstream code.

The Guardrail: Create an explicit Validation/Sanitization Node between Worker B and Worker C. This node must parse the incoming state variable using programmatic assertions. If the structural invariants fail, it updates the state with a rejection flag and forces a rollback/routing routine.

5. Data Privacy Leak via Telemetry (Student 5)
The Failure: The system correctly streams executions to LangSmith for tracking, but unintentionally leaks raw API keys, corporate database names, or user PII to cloud telemetry storage.

The Guardrail: Build a centralized State Redaction Interceptor. Programmatically scrub sensitive keys or match regular expressions for high-risk strings within the graph payload metadata before sending tracing logs to LangSmith or alternative external logging endpoints.

6. Context Window Explosion & Token Burn (Student 6)
The Failure: The multi-agent graph runs through multiple turns, creating a massive, redundant list of state["messages"]. This results in exploding input token costs and slow response latencies.

The Guardrail: Implement a specialized Context Management Node executing at the start of loop transitions. This node calculates total message tokens. If the system exceeds a specific length threshold, it programmatically summarizes past conversation histories, prunes intermediate tool outputs, and updates the state message window while preserving the system's core state values.

🛡️ THE CONTRACT RULE (MANDATORY)
Before a single student writes any individual guardrail code, the team must design and commit a shared Schema File (contract.py or contract.ts). This serves as the universal structural contract for the entire system's state management.

Python
# Example Language-Agnostic Concept (Python / Pydantic Example)
from pydantic import BaseModel, Field
from typing import List, Dict, Any, Optional

class AgentState(BaseModel):
    task_domain: str
    raw_input: str
    round_number: int = 0
    is_validated: bool = False
    error_log: Optional[str] = None
    analysis_payload: Dict[str, Any] = Field(default_factory=dict)
    sanitized_tool_calls: List[str] = Field(default_factory=list)
